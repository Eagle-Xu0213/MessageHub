第一阶段：只负责把新消息持续接进来。整理与分类规则下一阶段再设计。
实测结论（2026-11-15 · 屏幕已解锁 / 全群已授权）：微信 4.2 主窗口可见， 但消息区是 MMUIRenderSubWindowHW 自绘层——UIA 控件树 63 个节点、 0 条消息文本，TextPattern / ValuePattern / 原生子窗口均取不到正文。 这是客户端渲染架构限制，与解锁、白名单、窗口可见都无关， 因此「客户端 UIA 只读」当前采不到消息，不是配置问题。
可靠通道是下方「标准接入点」：任何能拿到新消息的工具 POST 进来即可实时入库并推送到消息流。
数据边界不变：不点击、不置前、不发送、不解密、不读原始聊天数据库； UIA 取不到精确消息时间时标记 capture_time，绝不伪称精确时间。

标准接入点 推荐 · 已验证

任何能拿到新消息的工具（导出器、桥接程序、推送脚本）调用一次即可：消息当轮入库、按指纹去重、 立刻出现在下方消息流。不依赖微信 / QQ 客户端控件结构，是当前唯一稳定可用的实时通道。 
POST http://127.0.0.1:8000/api/live/ingest
Content-Type: application/json

{
  "source_platform": "wechat",
  "conversation_id": "group_001",
  "conversation_name": "项目群",
  "sender_name": "张三",
  "sent_at": "2026-11-15T11:30:00+08:00",
  "text": "今天下午三点评审"
}
必填 text；建议 conversation_name sender_name sent_at source_platform conversation_id source_message_id。支持单条对象、数组批量、或 {"messages":[...]} 包装（单批上限 1000 条）。 不传 sent_at 时按采集时刻入库并标记 capture_time。
